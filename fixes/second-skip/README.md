# 事件点跳秒修复

**问题**：事件点倒计时的数字偶尔跳过一个（如 8 → 6），或者同一个数字显示两秒；悬浮条的秒数也会偶尔跳秒。更严重的是，主循环按整秒比对提醒时间，跳过的那一秒里的事件点胶囊 / 定时全屏提醒会**不弹出**，重复的那一秒则可能让事件点**弹出两个**。

**原因**：`EventPointReminder` 和 `UniversalTimer2` 都用普通的 1000ms `QTimer`（默认粗精度，允许 ±5% 误差，并被 Qt 对齐到它内部单调时钟的整秒、半秒等位置），再用 `QTime::currentTime()` / `secsTo()` 按墙上时间的整秒计算。单调时钟和墙上时间之间有一个固定的零头，每台机器、每次开机都不同。零头恰好让触发时刻落在墙上时间整秒前后几毫秒时，抖动几毫秒就会落到整秒的另一边：一次算成上一秒（重复），下一次跨过两秒（跳过）。所以只是“有时候”出现。

**修复**：两个计时器都改成单次触发的精确计时器（`Qt::PreciseTimer`），每次触发后重新安排在**下一个整秒（整 `update_interval`）刚过 50ms** 时触发，每次采样都落在一秒的中间。

在上一个修复（`countdown-fade`，以及 `countdown-blink` 的 `stop()`）之后应用。

## 应用

- 会用 git：在 Universal-Timer 根目录 `git apply second-skip-fix.patch`（需要先有 `stop()` 和淡入淡出修复）
- 不会用 git：用 `one-click/`，整个文件夹放进项目文件夹后，Linux 在该文件夹里运行 `bash apply.sh`，Windows 双击 `apply.bat`；`undo.sh` / `undo.bat` 撤销。一键包不依赖前面的修复。

## 验证

用 libfaketime 把墙上时间平移几毫秒（单调时钟不变），模拟“触发时刻贴着整秒”的机器：

| 墙上时间平移 | 修复前 | 修复后 |
| --- | --- | --- |
| 胶囊倒计时 -5ms | 跳过 10，18、9 显示 2 秒 | 无跳过 / 重复 |
| 胶囊倒计时 -40ms | 跳过 9，18、8 显示 2 秒 | 无跳过 / 重复 |
| 主循环 -5ms，35 秒、10 个事件点 | 悬浮条跳 5 秒、重复 5 秒；只弹出 8 个胶囊 | 33/33 次正常；10 个 |
| 主循环 -20ms | 悬浮条重复 1 秒；弹出 11 个胶囊（一个事件点弹了两次） | 33/33 次正常；10 个 |

修复后无论平移多少，胶囊和主循环的触发时刻都稳定在每秒的 .05～.07。打上补丁的完整程序能编译链接。一键应用工具（bash / PowerShell × LF / CRLF）结果与补丁逐字节相同，重复运行不会重复修改，撤销后与原文件一致。

注意：如果程序卡住超过约 1 秒（事件循环被阻塞），那一秒仍然会被跳过；这和计时器相位无关，本修复不处理。
